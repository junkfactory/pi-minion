# Changelog

## [0.2.1]

- Rename the public `agent` parameter to `minion` for `run_pi_minion`, `schedule_pi_minion`, and workflow steps. Existing agent files and internal agent handling are unchanged.

## [0.2.0]

- New specialized agents: markdown files in `~/.pi/agent/pi-minion/agents/` (filename stem = kebab-case name) whose body becomes the minion's system prompt — the shared operational tail is still appended — and whose frontmatter supplies optional `model`, `effort`, `tools`, `maxTurns`, `maxBudgetUsd`, and `timeoutMs` defaults. Pass `agent: "<name>"` to `run_pi_minion`, `schedule_pi_minion`, or a workflow step, with `model`/`effort` then optional; an explicit call param wins, then the file, then the config default. `help_pi_minion` lists `agents: [{name, description}]`. `tools` can only narrow `config.allowedTools` (an empty intersection is rejected, never widened) and it narrows the **claude adapter only** — every other adapter ignores the list (logged as `agent_tools_ignored`), so `tools: []` is an error for claude alone; an agent that defines no model/effort and a call that passes neither fails instructively, and invalid files are skipped with an `agent_invalid` lifecycle-log line. Agent jobs are titled `<agent>: <title>`, sub-sessions use `<agent>: <name>`, and schedule/workflow rows name the agent. Adds the `yaml` dependency for frontmatter parsing.
- New turn counter (current/max) across the UI: a job's turn progress shows as `N turns` (uncapped) or `N/M turns` (capped) on standalone job rows and workflow step rows (live and finished), as a `turn: N/M` badge in the detail-modal header, and as `· turn N/M` in the trail browser's steps-view labels and per-step detail modals. The count updates live on every turn start, is clamped to the cap when a capped run's stopping turn would show `maxTurns + 1`, and is simply absent for adapters that report no turn boundaries or for jobs whose first turn never starts. Finished jobs freeze the final counts into job meta, so the trail browser keeps showing them after the live registry drops the job.

## [0.1.0]

- New Troubleshooting entry: why a substring-looking `models.blocked`/`models.allowed` pattern like `*-contributor*` silently matches nothing against provider-qualified ids (minimatch `*` does not cross `/`), and why `**/*-contributor*` does. The README documents the `**/*` rule alongside its pattern rules.

- New `steer_pi_minion(id, message, deliverAs?)` tool: sends a mid-run message to a still-running job of this session. `deliverAs: "steer"` (default) lands after the current turn's tool calls and redirects the run; `"followUp"` queues the message for after the agent has no work left. Steering is supported by the pi and claude adapters only (agy and fm have no steering channel), and a settled job or a closed stdin channel rejects the message.
- New optional `maxTurns` cap on `run_pi_minion` and in the config: a whole number from 1 to 100000, unlimited when absent. The tool param overrides the config default; a run that reaches the cap is cancelled with a `maxTurns=N reached` note. Workflows accept `maxTurns` per step and at the workflow level (step overrides workflow, then the config default).
- `timeoutMs` is now an idle backstop rather than a wall-clock kill: every stdout line from the minion restarts the timer, so a long but productive run is never killed for taking too long and a stuck run's only kill is silence. A capped run is nudged once by steering ten turns before its cap (skipped when the cap is 10 turns or fewer, or the adapter has no steering channel), and each job's frontmatter now shows the resolved `maxTurns` (`maxTurns: none` when uncapped) so an unexpected cap can be traced.
- A job that verifiably finishes now has its child's stdin closed — the CLIs' orderly-shutdown signal — backed by the existing `SIGTERM`/`SIGKILL` escalation after a 5 s grace, so a child that ignores EOF cannot linger.
- The turn cap is now counted from each assistant turn's start rather than its completion (claude: the `message_start` stream event that opens the turn; agy: the response's first update), so a capped run stops before the turn after the cap runs at all; a turn that never finishes still counts. A `maxTurns` request on an adapter that reports no turn boundaries (none of the shipped four) is rejected instead of being silently unenforced.
- A stdin write that fails while a job is still running now surfaces as a warning on the job's result and closes the channel, so `steer_pi_minion` rejects later messages instead of reporting delivery; a turn cap whose stop frame cannot be written escalates to stopping the process. The failure is classified per write, so one whose error only surfaces after the run settled is still reported. `steer_pi_minion` now reports delivery only after the write callback confirms it.
- Scheduled jobs and workflows now pin `maxTurns` from the config default too (step, then workflow, then config), like `timeoutMs` and `maxBudgetUsd`, and pin an explicit no-cap when nothing sets one, so a later `pi-minion.json` edit can never retarget an existing schedule. A cap outside 1..100000 is rejected when the schedule or workflow is created — including an invalid workflow-level value that a step override would otherwise hide.
- README: corrected the run description (the adapter owning the requested model runs the job) and added `maxTurns` to both schedule signatures.
- Aligned dev dependencies with pi 1.5.0.
- A workflow step that fails, or reports its packet unworkable by ending its reply with a one-line reason then `[[STEP_BLOCKED]]`, now aborts the entire run: running steps are cancelled, pending steps are skipped. The single summary starts a turn carrying that reason in a `**Needs attention:**` line, so the packet can be revised and the workflow re-run; the interim mid-run failure alert (`formatWorkflowAlert`) is removed. The abort note trims a trailing period from the step's reason so it reads as one sentence.
